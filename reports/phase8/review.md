# Phase 8 review: findings and dispositions

The reviewer subagent reviewed the staged phase 8 work on 2026-10-24, using artifacts and datasheets only. It:

- traced every GPIO in the compiled devicetrees through U1's pads and the routed nets of both boards;
- checked power, clock and reset against the E73 and BQ24073 datasheets and Zephyr 4.1's sources;
- compared the keymap with the original;
- inspected the bootloader hex layout and the UF2 files;
- rebuilt everything twice.

Scratch material is in `scratch/review8/`.

It confirmed, with no findings:

- **Pins:** all 17 key GPIOs per half go to exactly the switch pads `pinmap.json` names. The LED pins go through R8/R9/R10 to the R/G/B cathodes. The charger-status pins go through D5/D4 to U2's PGOOD (7) and CHG (9).
- **Power, clock, reset:**
  - REG0 disabled, REG1 DC/DC; the module has REG1's inductors, and DCCH is unconnected.
  - RC 32 kHz clock calibrated at 500 ppm.
  - `gpio-as-nreset`.
  - The bootloader writes REGOUT0 = 3.3 V only from the erased default.
- **Bootloader:** nice!nano's flash layout, family 0xADA52840 for the application UF2s, no DFU or LED pins read or driven.
- **Keymap:** a faithful port; the positions and thumbs match duckyb's layout.
- **Pins and CI:** the pins match their sources; the ZMK images rebuild byte-identical.

No high-severity findings.

| # | Finding | Disposition |
|---|---|---|
| M1 | Nothing stops a half from receiving the other half's image. The LED outputs (push-pull, idle high) would then fight key switches shorting those pins to ground, and charger-status pins would read as keys. | **Fixed.** The LED outputs are open-drain (`GPIO_ACTIVE_LOW \| GPIO_OPEN_DRAIN`, generated by `gen_board.py`): they only pull a cathode low, so a pressed key never meets a driven-high pin. A wrong-half image now only shows dead or phantom keys. `firmware/README.md` says so. Compiled flags: 0x7 on all six LED pins. |
| M2 | After any reset while charging (wake from deep sleep, a flash, switching on while docked), the driver had no level measured on battery and reported VDDH's 4.4 V as full. | **Fixed for resets.** The last level on battery is kept in GPREGRET2, which survives soft resets and the wake from System OFF. Neither ZMK nor Zephyr uses it; ZMK's boot-mode flag and the Adafruit bootloader use GPREGRET. The driver restores it at init. **Remaining, documented:** after a power loss (battery disconnected), a half that starts charging reports full until its first sample on battery (`firmware/README.md`, the binding's description). |
| M3 | SETUP.md still recommended a Raspberry Pi Pico as the SWD probe. | **Fixed.** SETUP.md now asks for a probe whose I/O follows VTref down to 1.8 V, e.g. a J-Link: SEGGER lists the J-Link EDU Mini's target interface voltage as 1.8 V and 3.3 V, with a non-profit-educational licence. pyOCD needs SEGGER's J-Link software pack, which is now listed. The reviewer thought the EDU Mini was 3.3 V only; SEGGER's product page says otherwise. |
| M4 | The exit criterion needs a CI run that built and attached the firmware. | **Done.** CI run 40096653403 (commit aab083e) built and attached the images, byte-identical to the local build; recorded in `docs/PLAN.md`. |
| L1 | Bootloader builds weren't reproducible (`__DATE__`/`__TIME__` in the USB drive's file dates). | **Fixed.** `build_bootloader.sh` sets `SOURCE_DATE_EPOCH` to the pinned commit's date. Two builds now give identical hex and UF2 files. |
| L2 | lvgl and hal_stm32 came from Zephyr's manifest instead of ZMK's pins. | **Fixed.** Zephyr's import blocks them, so ZMK's pins apply (frozen manifest: zmkfirmware/lvgl f1db87ee, hal_stm32 4fcc3a3f). |
| L3 | A dead `if USB` block in `Kconfig.defconfig`. | **Fixed:** removed. The resolved config still has `USB_DEVICE_STACK` and `USB_NRFX` on both halves, and `ZMK_USB` on the left. |
| L4 | CHG edge cases: the 2 Hz fault blink, and the moment between PGOOD and CHG when docking, read as "charged". | **Fixed.** CHG is sampled 6 times over 600 ms and any active read counts as charging. "Charged" (100 %) needs two consecutive samples. |
| L5 | The first-flash steps didn't say the power switch must be on. | **Fixed** in `firmware/README.md`. |
| L6 | Only the left half's battery level reaches the host. | **Accepted, as in the owner's current config.** Enabling `ZMK_SPLIT_BLE_CENTRAL_BATTERY_LEVEL_FETCHING` and `_PROXY` in `urchin_pp.conf` would show both halves. |
| L7 | The firmware job's artifact upload lacked `if-no-files-found: error`. | **Fixed.** |
